Reflection Lab

A self-critiquing chart agent — draft, render, look, redraw.

This is a small agent that writes a chart, looks at what it drew, and rewrites it. Not a fancier prompt, not a second guess — a real reflection step where a stronger model gets handed the PNG and asked what went wrong. Two models, four steps, one lesson: structure beats instruction.

The interesting bits

Two models, two jobs

Cheap Haiku drafts; more capable Sonnet reviews. Reflection is the expensive step — drafting doesn’t have to be. Same principle as pair programming: junior writes, senior reviews.

Custom XML tags, not markdown fences

```python is ambiguous — models emit variants, nest fences inside docstrings, wrap prose by accident. <execute_python> is a token the model has no other reason to produce. One regex, zero ambiguity.

Structure the data, not the prompt

Pre-computing year, quarter, month in Python removes the “don’t concatenate date with time” failure mode. A prompt patch would ask nicely; a structural fix removes the surface.

Image-grounded critique

The reviewer sees the PNG, not the code. Critiquing your own code tells you what you intended. Critiquing the rendered artifact forces you to confront what actually came out.

exec() is a write tool

The loop runs arbitrary model-generated Python with full filesystem, network, and API-key access. Fine on synthetic data on a laptop; not sandbox-safe. A production version needs a subprocess or container boundary.

Failure surfaces, but isn’t acted on

run_generated_code catches exceptions and returns False. The plumbing for retry-on-failure is there — the driver just doesn’t consume it yet. The most useful next iteration.
