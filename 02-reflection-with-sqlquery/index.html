Question: “Which color of product has the highest total sales?”

v1 — naive 
SELECT color
FROM events
WHERE action = 'sale'
GROUP BY color
ORDER BY SUM(qty_delta * unit_price) DESC
LIMIT 1;
color
red
Wrong. Sales store negative qty_delta, so SUM(qty_delta*unit_price) is negative and DESC picks the least-bad seller.
v2 — reflected 
SELECT color, SUM(-qty_delta * unit_price) AS total_sales
FROM events
WHERE action = 'sale'
GROUP BY color
ORDER BY total_sales DESC
LIMIT 1;

Right. Negating qty_delta flips the sign; total is now a real revenue figure the critic can defend.

The event log, explained

State is derived, not stored

Every row is one event: insert, restock, sale, or price_update. Current stock, current price, revenue — all are aggregations across time.

Great for auditability. Awkward for the LLM: a query that looks simple (“what's the price?”) needs non-trivial SQL.

The sign trap

Sales record qty_delta = -1. Restocks record positive numbers. A first-pass revenue query almost always sums the raw delta and gets a negative total.

This is the class of bug reflection exists to catch.

Two critic variants

The lab ships refine_sql_text_only (critic sees only the SQL) and refine_sql_with_rows (critic also sees the returned rows).

The rows-aware critic is the one that reliably catches semantic bugs the text-only critic waves through.

SELECT-only guardrail

utils.run_sql rejects anything that isn't SELECT or WITH. The LLM cannot mutate the database even if it tries.

The critic call, in one snippet

# The move that makes it reflection rather than a second guess:
# hand the model the ROWS THAT CAME BACK, not just the SQL that produced them.
def refine_sql_with_rows(question, sql, rows, cols, schema, model):
    rendered = utils.rows_as_text(rows, cols, max_rows=20)
    prompt = f"""Review the SQL AND its output against the user's question.
The rows below are the actual result of running the SQL. If the rows do
not answer the question (wrong sign, empty, wrong grain, missing filter,
etc.), rewrite the SQL.

User question:
{question}

SQL that was executed:
{sql}

Rows returned ({len(rows)} total; showing up to 20):
{rendered}
"""
    return _parse(utils.get_response(model, prompt, system=SYSTEM),
                  fallback_sql=sql)
